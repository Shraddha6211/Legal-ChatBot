# Evaluation Guide for RAG System

This project now uses `eval.py` for comprehensive evaluation of the retrieval pipeline. It includes both **batch evaluation** (against a goldset) and **inline metrics display** (during queries).

## Quick Start

### 1. Build the Goldset
Generate evaluation questions from your vector database:

```bash
python eval.py build-goldset --sample-size 40
```

This creates `goldset.jsonl` with sampled questions. **Review the file manually** and delete/edit any bad rows before trusting evaluation results.

```bash
python eval.py build-goldset --sample-size 10  # For a quick test
```

### 2. Run Evaluation
Evaluate retrieval performance against the goldset:

```bash
python eval.py run --top-k 5
```

This outputs:
- **hit_rate_at_k**: Fraction of questions where correct chunk appears in top-k (= recall@k for single-relevant-doc goldsets)
- **precision_at_k**: Average of (1/k if hit, else 0) per question
- **mrr**: Mean Reciprocal Rank - rewards ranking correct chunk near the top
- **misses**: List of queries that didn't retrieve the correct chunk (inspect these!)

Results are saved to `eval_results.json`.

## Inline Metrics Display

When you ask a question in the Streamlit app:

1. **Metrics Card** shows:
   - Precision@k (% of top-k chunks that are relevant)
   - Relevant Count (# of chunks with similarity distance < 0.5)

2. **Detailed Metrics** expander shows:
   - Mean/min/max similarity distances
   - Distance threshold used for relevance classification

Relevance is determined by **cosine distance < 0.5** (threshold-based).

## Goldset File Format

Each line is a JSON object:

```json
{
  "question": "What are the composition, term, qualifications...",
  "gold_chunk_id": "eca6f2d483e5",
  "gold_chunk_text": "### Federal Legislature\n83. Federal Legislature..."
}
```

- `question`: Generated by LLM from the chunk
- `gold_chunk_id`: SHA256 hash of chunk text (survives re-chunking)
- `gold_chunk_text`: Full chunk text for manual review

## Workflow

### Initial Setup
1. Ensure ChromaDB is populated with chunks
2. Generate goldset: `python eval.py build-goldset`
3. Review `goldset.jsonl` and remove bad questions
4. Save your reviewed goldset

### Evaluation Cycle
1. Run: `python eval.py run --top-k 5`
2. Analyze results in `eval_results.json`
3. Investigate misses to improve retrieval
4. Iterate on chunking or retrieval parameters

### During Development
- Inline metrics automatically display with each query in Streamlit
- Use these for quick feedback during experimentation
- Use batch evaluation for rigorous performance measurement

### Change Top-k for Evaluation
```bash
python eval.py run --top-k 10  # Default is 5
```

## Interpreting Results

| Metric | Interpretation |
|--------|-----------------|
| **Hit Rate 1.0** | Perfect - all questions found relevant chunk in top-k |
| **Hit Rate 0.5** | 50% of questions found relevant chunk in top-k |
| **Precision 0.2** | With top-k=5, avg 1 relevant chunk per query |
| **MRR 0.9** | Excellent - relevant chunks ranked very high |
| **Misses** | Queries that failed - these need investigation |

## Troubleshooting

**Issue**: `FileNotFoundError: No goldset found`
- Run `python eval.py build-goldset` first

**Issue**: Hit rate is low
- Increase `--sample-size` to validate on more questions
- Check `eval_results.json` → `misses` to see what failed
- May indicate issues with chunking or retrieval strategy

**Issue**: slow build-goldset
- Reduce `--sample-size` for testing
- Each goldset entry requires an LLM call to generate the question

## Performance Notes

- Goldset generation: ~5-10 seconds per question (API calls to OpenAI)
- Evaluation run: ~2-5 seconds per question (retrieval + ranking)
- Use small `--sample-size` (10-20) for quick iteration
- Use larger (40-100) for reliable evaluation
